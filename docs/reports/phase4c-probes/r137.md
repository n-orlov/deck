# R137 probe audit — the header cursor's own key surface (GH #32)

Method: R137 spans tasks 012-015 (the `sidebarCursor` type, the shared
session-scoped guard, `c`/left/right fold-unfold, and their docs/help/footer
copy) and every one of its product hunks already lives on the current tree
at HEAD, so no scratch worktree is needed for this audit — the tree at
2752c9e cannot even build against these tests (`headerCursor`/`rowCursor`,
`cursorGroupID`, `guardSessionScopedKey` etc. do not exist there at all,
never mind behave differently), so "against 2752c9e" would prove nothing
about a specific behaviour beyond "the type didn't exist yet". Each of the
four probes below instead reverts that probe's own product hunk in place on
the landed tree, runs the named test with `ci/run.sh go test -count=1 -run
<Test> -v ./internal/tui/`, and then restores the hunk with `git checkout --
<file>` before the next probe — `git status --porcelain` is confirmed clean
between every probe and the fixed tree's own `ci/run.sh go test -count=1
./internal/tui/` is green (`ok internal/tui 7.278s`) at the end.

## Probe 1 — repeated `c` folds no more than one group

**Test:** `TestRepeatedCFoldsNoMoreThanOneGroup`
(`internal/tui/fold_unfold_test.go`).

**Which of the two:** the probe's own product hunk reverted — task 014's
`internal/tui/group.go`, `setGroupCollapsed`'s eviction removal. The hunk
reverted:

```go
-		if idx, ok := m.selected.SessionIndex(); ok && idx >= 0 && idx < len(m.sessions) && sessionGroupID(m.sessions[idx]) == groupID {
-			m.selected = headerCursor(groupID)
-		}
 	} else if m.collapsedGroups != nil {
 		delete(m.collapsedGroups, groupID)
 	}
+	m.selected = m.nearestVisibleSelection(m.selected)
```

(i.e. restoring the pre-014 unconditional `nearestVisibleSelection` eviction
this task deleted, unchanged all the way back to the launch sha 2752c9e).

**Exact failure produced:**

```
=== RUN   TestRepeatedCFoldsNoMoreThanOneGroup
    fold_unfold_test.go:273: after 2 repeated c presses, 2 groups are collapsed (a=true b=true c=false) -- want at most 1
--- FAIL: TestRepeatedCFoldsNoMoreThanOneGroup (0.00s)
FAIL
FAIL	github.com/n-orlov/deck/internal/tui	0.004s

```

The old eviction walks the cursor off the group just folded and onto a
session in a different group, so a second, unrelated-looking `c` press
collapses that group too — exactly the defect task 014's commit message
(`1804a72`) predicted and this run reproduces verbatim in substance (the
group labels differ only because this run's own fixture uses `a`/`b`/`c`
rather than `idA`/`idB`).

## Disposition

All four probes fail against the landed tree with that probe's own product
hunk reverted, and the fixed tree itself is green
(`ci/run.sh go test -count=1 ./internal/tui/` → `ok internal/tui 7.278s`,
`git status --porcelain` empty). R137 is audited: the repeated-`c` guard
(task 014), header reachability for `g`/`G` (task 012), fold/unfold reaching
a defined-but-empty group (task 014), and the shared session-scoped guard's
inertness table (task 013) are each backed by a test that genuinely exercises
its own fix rather than one that would also pass against the unfixed
behaviour.
