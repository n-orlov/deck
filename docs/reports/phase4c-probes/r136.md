# R136 probe audit — the selection viewport follows the cursor (GH #31)

Method: a scratch git worktree (`git worktree add .scratch-009 2752c9e`, the
launch sha, before task 007's `m.setSelection`/`followSelectionViewport`
seam existed at all) with task 008's own test file
(`internal/tui/viewport_follow_gestures_test.go`) copied in unchanged, plus
one scratch-only helper file (`probe009_selectionspan.go`, never committed)
providing a standalone copy of the `selectionSpan` function so the test file
compiles without also copying in task 007's
`selection_viewport_seam_test.go` — that file itself calls `m.setSelection`,
which does not exist at 2752c9e, and pulling it in would fail to build for a
reason that has nothing to do with R136's own behaviour. Every other
function the test file uses (`sidebarEntries`, `computeLayout`,
`sidebarEntryContentWidth`, `clampSidebarScroll`, `sidebarVisibleEntries`,
`sidebarLineRow`/`sidebarLineOther`, `MinRows`, plus `key`/`wheelDown`/
`findRow` from the package's own existing test helpers) already exists at
2752c9e unchanged. Each run is `ci/run.sh sh -c 'cd .scratch-009 && go test
-count=1 ./internal/tui/ -run <Test> -v'` — `ci/run.sh` always binds
`$RALPHD_HOST_WORKSPACE` at a fixed `/w` workdir, so a probe run must `cd`
into the scratch worktree itself inside that container; running `ci/run.sh
go test ...` directly from inside `.scratch-009` silently tests the outer,
unreverted tree instead. The worktree was removed
(`git worktree remove --force .scratch-009`) before this report was
written; `git status --porcelain` is clean and the fixed tree's own
`ci/run.sh go test -count=1 ./internal/tui/` is green
(`ok internal/tui 7.202s`).

All eleven probes below are the eleven test functions task 008 landed in
`internal/tui/viewport_follow_gestures_test.go`; each already carries, in
its own doc comment, the exact failure text it predicts against 2752c9e —
the runs below confirm every one of those predictions verbatim.

## Probe 10 — wheel-return (SPEC §11.8's documented wheel independence)

**Test:** `TestViewportWheelDriftIsNotPreservedAfterDown` — the wheel is
free to drift `sidebarScroll` away from the selection without ever moving
it, but the very next selection move must snap the viewport back into view
rather than leaving the wheel's own drifted offset in place. At 2752c9e
`down` assigns `m.selected` directly with no follow at all, so
`sidebarScroll` is left completely untouched by the keypress.

**Exact failure produced:**

```
=== RUN   TestViewportWheelDriftIsNotPreservedAfterDown
    viewport_follow_gestures_test.go:352: sidebarScroll = 40 after down, unchanged from the drifted wheel offset 40 -- the wheel's offset was preserved instead of the cursor snapping back into view
--- FAIL: TestViewportWheelDriftIsNotPreservedAfterDown (0.01s)
FAIL
```

## Probe 11 — 80x24 flush floor

**Test:** `TestViewportFlushDegradesAt80x24WithNoBlankTail` — at the
supported minimum terminal size, `G` must land exactly at
`clampSidebarScroll`'s own flush bound with no blank padding trailing the
real content. At 2752c9e `sidebarScroll` is left at its zero value instead
of the flush bound.

**Exact failure produced:**

```
=== RUN   TestViewportFlushDegradesAt80x24WithNoBlankTail
    viewport_follow_gestures_test.go:384: sidebarScroll = 0 after G at 80x24, want flush at 41 (no room to fight the clamp at this floor)
--- FAIL: TestViewportFlushDegradesAt80x24WithNoBlankTail (0.00s)
FAIL
```

## Disposition

All eleven probes fail against the unfixed tree at the launch sha 2752c9e
and pass against the landed tree (`ci/run.sh go test -count=1
./internal/tui/` → `ok internal/tui 7.202s`). R136 is audited: the nine
per-binding rows of its table (up/k, down/j, pgup, pgdown, g, G, space, c,
`/` filter query edit) plus the wheel-return probe and the 80x24 flush-floor
probe are each backed by a test that genuinely exercises the viewport-follow
fix rather than one that would also pass against the unfixed tree.
