# R138 probe audit — header click works while a preview is live (GH #33)

Method: a scratch git worktree (`git worktree add .scratch-r138 HEAD`, HEAD ==
`1ba7007`, task 005/B.1's landed commit) with B.1's own product hunk
reverted — `internal/tui/mouse.go`'s `resolveSidebarPress` extraction and
`internal/tui/tui.go`'s interactive-mode press branch, both back to their
shapes at the launch sha `2752c9e` (`git show 1ba7007 -- internal/tui/mouse.go
internal/tui/tui.go | git apply -R`) — with the test file
(`mouse_interactive_header_press_test.go`, already landed by B.1) left
exactly as it is. Each run is `ci/run.sh sh -c 'cd .scratch-r138 && go test
-count=1 ./internal/tui/ -run <Test> -v'` — `ci/run.sh` always binds
`$RALPHD_HOST_WORKSPACE` at a fixed `/w` workdir, so a probe run must `cd`
into the scratch worktree itself inside that container, not merely be
launched from it; running `ci/run.sh go test ...` directly from inside
`.scratch-r138` silently tests the outer, unreverted tree instead. The
worktree was restored (`git checkout -- internal/tui/mouse.go
internal/tui/tui.go`) and removed (`git worktree remove --force
.scratch-r138`) before this report was written; `git status --porcelain` is
clean and the fixed tree's own `ci/run.sh go test -count=1 ./internal/tui/`
is green (`ok internal/tui 7.251s`).

## Probe 1 — the interactive header-press probe

**Test:** `TestInteractiveHeaderPressTogglesCollapseWithoutResize`
(`internal/tui/mouse_interactive_header_press_test.go`) — a left press on a
group header while `m.interactive` is true must reach the shared
`resolveSidebarPress` resolver, toggle that group's collapse, return
`persistCollapsedGroups`'s command, and leave `m.interactive` true with no
geometry/resize call (`interactiveScrollOffset`/`previewFitSessionID`
survive untouched).

**Product hunks reverted:** `internal/tui/mouse.go`'s `resolveSidebarPress`
extraction (back to `handleMousePress`'s own inline `hitPanelSidebar`
switch, no shared resolver) and `internal/tui/tui.go`'s interactive-mode
press branch (back to testing `hit.panel == hitPanelSidebar && hit.target ==
hitTargetRow` only, so a header/collapsed-strip hit falls through to
`beginInteractiveSelection` and, since the test's `m.interactiveGrid` is
nil, no-ops).

**Exact failure produced**
(`ci/run.sh sh -c 'cd .scratch-r138 && go test -count=1 ./internal/tui/ -run TestInteractiveHeaderPressTogglesCollapseWithoutResize -v'`):

```

--- FAIL: TestInteractiveHeaderPressTogglesCollapseWithoutResize (0.02s)
FAIL
```

## Probe 2 — the list/interactive parity probe

**Test:** `TestHeaderPressParityBetweenListAndInteractiveMode`
(`internal/tui/mouse_interactive_header_press_test.go`) — the same header
press, against the same starting model modulo `m.interactive`, must collapse
the same group by the same amount whether or not interactive mode owns the
keyboard, so the two modes cannot silently diverge again.

**Product hunks reverted:** the same two hunks as probe 1 (they are B.1's
whole product change — one resolver extraction in `mouse.go`, one call-site
swap in `tui.go` — there is no narrower hunk that isolates parity alone from
the header-press behaviour itself).

## Disposition

Both probes fail against B.1's product hunk reverted and pass against the
landed tree (`ci/run.sh go test -count=1 ./internal/tui/` → `ok internal/tui
7.251s`). R138 is audited: its two success-criteria assertions (the header
press toggling collapse without leaving interactive mode, and parity between
list and interactive mode) are each backed by a probe that genuinely
exercises the fix rather than one that would also pass against the unfixed
tree. A third test landed by B.1,
`TestInteractiveCollapsedStripPressRestoresLayout`, covers the
collapsed-strip half of the same resolver but is not one of this task's two
named probes.
